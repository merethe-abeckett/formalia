## 一句话

Lean 4 是一种编程语言，也是一个**证明助手**：数学命题和证明都可以写成代码，由电脑一步一步检查证明对不对。只要代码能通过检查，证明就没有漏洞。

## 为什么需要它

传统的数学证明写在纸上，靠人来审。证明一长，审稿人也可能看漏。Lean 不靠信任：每一步都必须由明确的规则推出来，少一步、错一步，代码就通不过。

最终负责检查的是 Lean 里一个很小的程序，叫**内核**。不需要相信作者，也不需要相信写证明的 AI，只需要相信这个内核。

## 一个最小的例子

```
theorem two_add_two : 2 + 2 = 4 := rfl
```

读法是：**定理** 名字 **:** 命题 **:=** 证明。

- `two_add_two` 是这条定理的名字；
- `2 + 2 = 4` 是要证明的命题；
- `rfl` 是证明，意思是“两边算出来是同一个东西”。

如果把命题改成 `2 + 2 = 5`，Lean 会报错，这段代码就通不过。

## 命题就是类型，证明就是程序

Lean 背后有一个很漂亮的想法：**每个命题都是一种类型，一个证明就是这种类型的一个值。** 证明“命题 P 成立”，就是写出一个类型为 P 的程序。程序能通过类型检查，证明就成立。

所以在 Lean 里，“检查证明”和“编译代码”是同一件事。

## 看懂 Formalia 里的一条表述

这是哥德巴赫猜想的一条表述（#20261014-01）：

```
def S20261014_01 : Prop :=
  ∀ n : ℕ, 2 < n → Even n → ∃ p q : ℕ, Nat.Prime p ∧ Nat.Prime q ∧ n = p + q
```

逐个符号翻译：

- `def S20261014_01 : Prop :=`：定义一个名叫 S20261014_01 的**命题**（Prop 就是“命题”这种类型）；
- `∀ n : ℕ,`：对每个自然数 n；
- `2 < n → Even n →`：如果 n 大于 2，并且 n 是偶数，那么；
- `∃ p q : ℕ,`：存在自然数 p 和 q，使得；
- `Nat.Prime p ∧ Nat.Prime q ∧ n = p + q`：p 是素数，q 是素数，而且 n = p + q。

注意这里只是**写下了命题**，没有证明。Formalia 登记的每条表述都是这样一个 `def … : Prop`。如果有人证明了它，证明会写成：

```
theorem 某个名字 : Registry.Goldbach.S20261014_01 := …
```

## Mathlib：大家共用的数学库

`Nat.Prime`（素数）、`Even`（偶数）这些概念不是 Lean 自带的，来自 **Mathlib**。Mathlib 是全世界数学家和程序员一起维护的数学库，已经收录了数十万条定义和定理，从基础算术到代数几何都有。

Mathlib 一直在更新，名字和定义的细节偶尔会变。所以 Formalia 把 Lean 和 Mathlib 的版本**钉死**，每个表述页都写着检查时用的确切版本。

## 几个常见的词

- **sorry**：占位符，意思是“这一步先欠着”。含 sorry 的代码能编译，但不算证明。
- **native_decide**：让电脑把一个计算编译成普通程序直接跑出结果，跳过内核的检查。用了它，就等于除了内核以外还要相信编译器。
- **公理**：不需要证明、直接承认的前提。Lean 的标准公理只有三条：`propext`、`Classical.choice`、`Quot.sound`，普通数学都建立在它们之上。用了别的公理，就是多加了假设。
- **内核**：Lean 里最终负责检查证明的那一小段程序。

所以 Formalia 的检查器会看：有没有 sorry、用了哪些公理、有没有 native_decide。用了 native_decide 的证明，登记库不直接相信，而是让内核把那一步重新算一遍，算出来一致才登记，并在页面上标出感叹号。

## 机器能保证什么，不能保证什么

**能保证**：如果一个证明通过了检查，那么这段 Lean 代码写的命题确实成立。

**不能保证**：这段 Lean 代码是不是忠实地表达了原来的猜想。比如把“大于 2”误写成“大于 200”，或者某个定义和数学家心里的意思不一样，机器都发现不了，因为它只检查代码本身。

这正是 Formalia 存在的原因：把每一种写法固定下来，给它永久编号，记录谁证明了哪个编号。至于哪种写法忠实于原猜想，留给数学家讨论。

## Lean 已经做到的事

- **液体张量实验**（2022 年）：菲尔兹奖得主 Peter Scholze 对自己一个复杂证明的正确性没有把握，向社区发起挑战。数学家们用 Lean（当时是 Lean 3）完整验证了它。
- **多项式 Freiman–Ruzsa 猜想**（2023 年）：Gowers、Green、Manners、Tao 证明这个猜想后，社区只用了大约三周，就在 Lean 4 里完成了形式化。
- **AlphaProof**（2024 年）：Google DeepMind 的 AI 系统在国际数学奥林匹克竞赛题上达到银牌水平，它给出的证明就是 Lean 代码，可以由机器直接检查。
