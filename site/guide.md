## 一分钟看懂

- **猜想**：一个用自然语言说的数学命题，比如“每个大于 2 的偶数都是两个素数之和”。每个猜想在 Formalia 有一个页面。
- **表述**：把猜想写成 Lean 4 代码的一种写法，形如 `def S20261014_01 : Prop := …`。同一个猜想可以有很多种写法，每种写法一个**永久编号**，比如 `#20261014-01`。编号指向的代码永远不变。
- **证明**：某人或某个 AI 提交“我证明了 #20261014-01”和证明代码。机器编译检查通过才登记。证明的是这段 Lean 代码，不是原猜想；两者是否等价，留给数学家讨论。

所以一个猜想页就像维基百科的消歧义页：上面列出这个猜想的所有已知写法。哪一种写法忠实于原猜想，Formalia 不下结论，留给数学家判断。

## 怎样读一个表述页

1. **基本信息**：编号、提交者、日期、来源、许可，以及检查时用的 Lean 和 Mathlib 版本。
2. **Lean 代码**：登记的原文。冒号后面、`:=` 后面那部分就是命题本身。
3. **检查器报告**：机器自动检查的结果。能否编译、有没有 `sorry`（未完成的证明）、有没有 `native_decide`（绕过内核的计算），用到了哪些公理。只用 `propext`、`Classical.choice`、`Quot.sound` 三条标准公理才算干净。
4. **定义链**：表述里直接用到的每个名字来自哪里。绝大多数来自 Mathlib；如果表述自己定义了新概念，会单独标出“自定义定义”，这是最需要人仔细看的地方。
5. **AI 导读**：AI 对每个定义的解释和逐句翻译，可以在下面直接向它提问。它可能出错，只解释代码，不评价表述好坏。
6. **非正式复述**：提交者自己对代码的理解。
7. **证明**：谁、何时证明了这个编号，证明代码在哪里，机器验证的结果。
8. **编辑历史**：这一条被谁改过什么。

## 不会 Lean 也能做的事

- 给表述补一段**非正式复述**或**外部链接**：点表述页上的“编辑本条信息”。
- 给猜想补**中文名**或**参考资料**：在猜想页点“编辑猜想信息”。
- 写一篇**解读**：这段 Lean 代码说了什么、和别的写法有什么不同、从证明里能读出什么。点表述页信息表里“解读”一行的“写一篇”，或在[解读](../essays/index.html)页点“写一篇解读”。解读是作者的个人观点，谁都可以修改。

## 登记一条新表述

1. 在猜想页点“＋ 新增一条表述”，或在首页点“＋ 登记一条表述”（也可以顺便登记一个新猜想）。
2. 在 **import** 里每行写一个 Mathlib 模块名，例如 `Mathlib.Data.Nat.Prime.Defs`。
3. 在 **命题** 里只写命题本身，例如：`∀ n : ℕ, 2 < n → Even n → ∃ p q : ℕ, Nat.Prime p ∧ Nat.Prime q ∧ n = p + q`。系统会自动包成 `def S<编号> : Prop := …`。
4. 需要自己定义概念时，写在 **辅助定义** 里。
5. 选来源类型和许可。改编别人的作品要填来源链接，并选与原作兼容的许可。
6. 提交后会跳到状态页，几分钟内显示结果。

为了安全，代码只能用 Lean 的一个子集。下面这些会被拒绝：`#eval` 等 `#` 开头的命令、`@[…]` 属性、`macro`、`syntax`、`set_option`、`IO`、字符串、`sorry`、`native_decide`。import 只能来自 Mathlib 或 Batteries。

## 提交一个证明或证否

每条表述都自带它的**否命题**，登记在同一个编号下。比如表述 #20261014-01 是 `Registry.Goldbach.S20261014_01`，它的否命题 ¬#20261014-01 就是 `¬ Registry.Goldbach.S20261014_01`。

- **证明**：证明命题本身成立。
- **证否**：证明否命题成立，也就是说这条表述不成立（比如找到了反例）。

两种声明都在表述页上登记：点“声明证明了这条表述”或“声明证否了这条表述”。证明可以放在**公开的 GitHub 仓库**里（填仓库、完整的 40 位提交号、定理所在模块），单个文件也可以**直接粘贴**。粘贴的时候可以先点“在 Lean 4 Web 中试编译”，在浏览器里马上看看能不能编译。Lean 4 Web 用的是最新版 Mathlib，结果只作参考，以提交后的正式验证为准。

要求：

1. 只依赖 Mathlib v4.29.0 和 Lean 4.29.0。版本定死，不接受其他版本：用别的版本写的证明，请先移植。
2. 用 `import Conjectures.<猜想>.S<编号>` 导入表述，例如 `import Conjectures.Goldbach.S20261014_01`。
3. 定理的类型必须**正好是**命题或否命题本身。证明写成 `theorem MyProof.goldbach : Registry.Goldbach.S20261014_01 := …`，证否写成 `theorem MyProof.no : ¬ Registry.Goldbach.S20261014_01 := …`。在证明里展开定义没问题，但不能改写或改弱定理的类型。
4. 仓库里只会拉取模块顶层名对应的 `MyProof.lean` 和 `MyProof/` 目录下的 `.lean` 文件，不用你的 `lakefile`，所以不能依赖别的库。
5. 不能有 `sorry` 或自定义公理。
6. **可以用 `native_decide`，但会标出感叹号。** `native_decide` 让电脑直接运行编译后的程序算出结果，本来需要额外信任编译器，而且它生成的辅助公理谁都能伪造。所以登记库不信这一步：验证时会让 Lean 内核把同样的计算重新算一遍，结果一致才登记，页面上标出“！native_decide”。内核算不动的计算会被拒绝。

提交后，机器会：

1. 编译你的证明；
2. 在全新的环境里检查定理的类型、所用公理，并用 Lean 内核重放；
3. 全部通过才登记，页面上会显示“验证通过”和运行记录。不通过会说明原因，不登记。

编译最长 290 分钟，超时按未能验证处理。通过之后如果发现问题，任何人都可以提出质疑，按[提删流程](https://github.com/merethe-abeckett/formalia/blob/main/docs/DELETION.md)处理。

### 声明的编号和规则

- **编号**：每条通过验证的声明都有一个永久编号，形如 `P20261015-01`，即登记日期加当天的序号，全库统一，永不复用。证明和证否共用这一套编号。
- **先后**：谁先谁后，以登记库收到并验证通过的登记时间为准。表单里的“声称日期”是提交者自己填的，只作参考。
- **声称方是自称**：登记库不核实身份，页面上标为“自称”。以机构或 AI 模型的名义声称时，请附上公告链接；没有公告的会标出“未附公告”。
- **存档**：粘贴的证明直接保存在登记库里。GitHub 仓库里的证明验证通过后，登记库也会存一份副本（`Proofs/<声明编号>/`），原仓库删了也查得到。
- **验证不等于背书**：机器验证的是“这段代码证明了这个 Lean 命题”，不是“证明了原猜想”，也不代表登记库认可这个结论。
- **版本不升级**：登记库的 Lean 和 Mathlib 版本保持钉死。将来如果不得不升级，所有证明都要在新版本上重新验证，过不了的就标为“在新版本上未通过”，原来的记录保留。

## 提交之后

- 机器检查格式；新增表述还要编译 Lean、运行检查器和独立复核，大约三到五分钟。
- **通过**：直接写入，网站几分钟后更新。
- **没通过**：状态页会写明原因，比如编译错误的那一行。改好后重新提交即可。
- 两个人同时改同一处时，后提交的人会看到“编辑冲突”，刷新后在最新内容上重做。

## 不接受什么

- **等价性争论**：“这条不算真正的哥德巴赫猜想”不是修改或删除的理由。觉得现有写法都不对，就登记一种新写法。
- **评价性文字**：条目里只写事实。

## 常见问题

**为什么不能直接改别人的 Lean 代码？** 因为“某人证明了 #20261014-01”这句话必须永远指向同一段代码。要改代码，就登记一条新表述，旧编号保留。

**我的提交为什么没通过？** 打开状态页看原因。最常见的是 Mathlib 里的名字写错，或用了上面列出的被禁写法。

**可以在自己电脑上检查吗？** 可以。每个表述页底部有“自己验证”的命令，也可以点“在 Lean 4 Web 中打开”在浏览器里试编译。

**中国大陆能用吗？** 网站和编辑表单都不依赖 GitHub 账号。GitHub 页面打不开也没关系，状态页会显示同样的结果。

**我的 IP 会被公开吗？** 不会。公开的只有由 IP 派生的匿名编号，详见[隐私与编辑规则](privacy.html)。
